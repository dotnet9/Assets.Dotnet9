# .NET 工控概念科普——入门篇：写给 .NET 开发者的大白话版

## 开始之前

这个系列之前的几篇，都是从某个具体问题切入的：聊过"实时性"，聊过 PLC 的扫描周期，聊过下位机和固件，也聊过 SCADA、MES、ERP 的边界。有朋友反馈：能不能有一篇"从零开始"的，把这些概念用大白话串一遍？

好，这篇就是。

你不需要任何工控背景，只要会一点 C#，就能看懂。看完这篇，你再去读系列里其他几篇，会顺畅很多。

## 一、工控到底是个啥？

一句话：**让计算机替人去"看"机器、"管"机器。**

工厂里有一台灌装机，以前需要老师傅盯着：看压力表有没有超、听电机声音对不对、温度高了就手动降速。现在我们想用程序来做这些事——程序得能"读"到机器的状态，也能"发命令"给机器。

这套"用软件管机器"的技术，就叫**工业控制**，简称**工控**。

而你写的 .NET 程序，就干两件事：

1. **读**：不断问机器"你现在什么状态？"
2. **写**：给机器下命令"转速给我降到 1200"。

就这么朴素。剩下的所有概念，都是围绕这两个动作展开的。

## 二、现场的两兄弟：上位机和下位机

进到车间，你会发现有两类"电脑"在配合干活：

- **上位机**：就是你这台跑着 .NET 程序的电脑。它离机器"远"一点，负责管理、监控、存数据、画界面。它自己是干不了体力活的。
- **下位机**：直接"贴"在设备上的控制器，比如 PLC、单片机。它负责真正的体力活：读传感器、控制电机、开关阀门。

打个比方：

> 上位机是**指挥部的参谋**，下位机是**一线的班长**。参谋看得全、算得快，但不碰设备；班长拿着对讲机，真正带着设备干活。

**上位机和下位机必须配合**。参谋再聪明，没有班长执行，命令落不了地；班长再能干，没有参谋统筹，就是个闷头干活的莽夫。

顺带解开一个常见困惑：**固件**是什么？固件就是烧录在下位机里的程序——出厂就写死在里面，一般不归你管。但注意一个坑：**下位机升级固件后，通信行为可能变**，你的上位机代码一行没改，却突然连不上了。遇到这种"灵异事件"，先问一句：最近是不是升级固件了？

## 三、PLC 是怎么干活的：读、算、写

PLC 是最常见的下位机，它的脑子构造特别简单，简单到让人放心。它不会像 PC 上的程序那样又是多线程又是事件回调，它就闷头重复三步：

1. **读**：把所有输入扫一遍——传感器通没通、按钮按没按、温度多少，全部拍一张"快照"存起来。
2. **算**：按你写好的逻辑，基于这张快照算一遍，该输出什么。
3. **写**：把结果刷新到输出——电机转不转、阀门开不开。

这三步叫一个**扫描周期**，通常几毫秒到几十毫秒就转一圈，循环往复。

为什么这么"笨"的设计反而可靠？因为它**确定**。比如周期是 10ms，那任何输入的变化，最迟 10ms 后就会被处理，早一点晚一点都不会发生——每一圈都是这个时间。工业现场最怕的不是慢，而是"这次 5ms、下次 500ms"的不确定。

这跟 Web 开发的直觉正好相反：Web 追求"快"，工控追求"稳"。这个差异是两个世界最重要的分水岭。

对我们上位机开发者的直接影响是：**你读 PLC 数据的频率，再快也快不过它的扫描周期**。周期 10ms，你 1ms 读一次，读到的也是重复的旧值，纯属浪费。

## 四、上位机和 PLC 怎么对话：说"普通话"

参谋和班长之间得有对讲机，上位机和下位机之间得有通信协议。初学者最常碰到两个：

- **Modbus TCP**：工控界的"普通话"。简单、古老、哪儿都通。本质上就是读写一张"地址表"：3 号地址存温度、5 号地址存转速……你按地址去读和写就行。缺点是它不太智能，没有安全机制，地址表还得对着厂家手册查。
- **OPC UA**：新一代的"商务沟通"。每个数据点自带名字、单位、说明（比如"1 号炉温度，单位℃"），不用查手册猜地址；还带加密和权限控制，跨厂商互通性好。

新手建议：**第一次通信实验就从 Modbus TCP 开始**，因为最简单、资料最多；等跑通了，再玩 OPC UA。

## 五、读到的数据放哪儿？

数据攒起来之后，一般分两路存放：

- **高频的传感器数据**（每秒成百上千条的波形、温度曲线）→ 放**时序数据库**，比如 InfluxDB。它专为"按时间写、按时间查"优化，一天几百万条也不怕。
- **业务数据**（某个班次生产了多少件、哪台设备报警过）→ 放**关系数据库**，比如 SQLite、SQL Server。适合结构化的记录和统计。

一句话记住：**波形进时序库，台账进关系库**。别把高频波形硬塞进 SQL Server 再拼命加索引，也别拿 InfluxDB 去做复杂的多表关联。

## 六、再往上：SCADA、MES、ERP，各管一层

数据存好了，不同的人要从不同的高度看它。把工厂想成一座金字塔，三层各有一个系统：

| 系统 | 金字塔位置 | 比喻 | 管什么 |
| --- | --- | --- | --- |
| SCADA | 底层 | **门卫监控室** | 实时盯着设备：画面、报警、曲线，秒级响应 |
| MES | 中层 | **车间主任** | 管生产过程：排产、报工、追溯质量 |
| ERP | 顶层 | **公司总部** | 管钱和资源：订单、库存、财务 |

新手最容易犯的错，就是搞不清边界。老板说"让 ERP 看设备温度"，你一头扎进 ERP 里写 Modbus 轮询——这就好比让公司总部直接去拧车间的螺丝。正确的做法是：**你写的上位机把温度采集上来，存进数据库，ERP 从数据库里取**。让管钱的只管钱，拧螺丝的专心拧螺丝。

## 七、全景图：你的程序站在哪

把前面所有概念串起来，一张图就出来了：

```
设备层：  PLC / 传感器 / 电机 / 阀门
   ↓ Modbus TCP / OPC UA
采集层：  ★ 你的 .NET 程序（轮询、清洗、换算、报警）
   ↓ 写入
数据层：  时序库（波形）+ 关系库（业务）
   ↓ 读取
业务层：  MES（排产、追溯）
展示层：  WPF / WinForm / Web 看板
企业层：  ERP（订单、财务）
```

作为 .NET 开发者，你的主战场是**采集层**：从 PLC 读数据、清洗换算、判断报警、写入数据库。这一层写扎实了，上层的一切才有饭吃。

## 八、入门路线图

如果这篇看懂了，建议按这个顺序动手：

1. **跑通一次 Modbus TCP 通信**：用 NModbus 之类的库，从模拟器（如 Modbus Slave）读几个寄存器，体会"按地址读写"。
2. **理解扫描周期**：故意用比 PLC 周期更快的频率去读，观察你拿到的是不是重复值。
3. **存数据**：把读到的温度按时间写进 SQLite 或 InfluxDB，画一条曲线。
4. **加一层业务判断**：温度超 80℃ 就记一条报警，写进关系库。
5. **回头精读系列其他几篇**，把"确定性和实时性""固件升级的坑""三层系统边界"这些概念补深。
